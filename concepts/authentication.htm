Authentication

This section covers authentication methods for the Qualys platform and container registries.

Qualys Platform Authentication

API Access Token

All integrations authenticate with the Qualys platform using bearer tokens:

Authorization: Bearer <access_token>

Generating an Access Token

  1. Log in to the Qualys platform
  2. Navigate to Administration > User Management
  3. Select your user or create a service account
  4. Under API, generate a new token
  5. Ensure Container Security scope is enabled
Important

Store tokens securely using secrets management. Never commit tokens to version control.

Agent Authentication

Kubernetes sensors and agents use activation credentials:

Credential Description Use
Activation ID Unique identifier for agent activation Cloud Agent, Container Sensor
Customer ID Your Qualys customer identifier Cloud Agent, Container Sensor

Container Registry Authentication

Public Registries

Public images from Docker Hub and other public registries require no authentication.

Amazon ECR

Use IAM role-based authentication:

# IAM Policy for ECR access
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ecr:GetAuthorizationToken",
                "ecr:BatchCheckLayerAvailability",
                "ecr:GetDownloadUrlForLayer",
                "ecr:BatchGetImage"
            ],
            "Resource": "*"
        }
    ]
}

Azure Container Registry

Use Service Principal authentication:

# Create Service Principal
az ad sp create-for-rbac --name "qualys-scanner" --skip-assignment

# Assign AcrPull role
az role assignment create \
  --assignee <sp-app-id> \
  --role AcrPull \
  --scope /subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.ContainerRegistry/registries/<acr>

Store credentials:

  • ACR_APPLICATION_ID - Service Principal application ID
  • ACR_CLIENT_SECRET - Service Principal client secret

Google Container Registry / Artifact Registry

Use service account key authentication:

# Create service account
gcloud iam service-accounts create qualys-scanner

# Grant access
gcloud artifacts repositories add-iam-policy-binding REPO \
  --location=LOCATION \
  --member="serviceAccount:qualys-scanner@PROJECT.iam.gserviceaccount.com" \
  --role="roles/artifactregistry.reader"

# Create key
gcloud iam service-accounts keys create key.json \
  --iam-account=qualys-scanner@PROJECT.iam.gserviceaccount.com

Private Docker Registry

Use username/password or token authentication:

# Docker login
docker login registry.example.com -u username -p password

# Or use environment variables
DOCKER_USERNAME=username
DOCKER_PASSWORD=password
DOCKER_REGISTRY=registry.example.com

Secrets Management

GitHub Actions

Store secrets in repository or organization settings:

Settings → Secrets and variables → Actions → New repository secret

AWS Secrets Manager

aws secretsmanager create-secret \
  --name qualys-api-token \
  --secret-string "your-token-here"

Azure Key Vault

az keyvault secret set \
  --vault-name my-vault \
  --name qualys-api-token \
  --value "your-token-here"

Kubernetes Secrets

kubectl create secret generic qualys-credentials \
  --from-literal=activation-id=YOUR_ID \
  --from-literal=customer-id=YOUR_CUSTOMER_ID \
  -n qualys-system

External Secrets Operator

apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: qualys-credentials
  namespace: qualys-system
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: vault-backend
    kind: ClusterSecretStore
  target:
    name: qualys-credentials
  data:
    - secretKey: activation-id
      remoteRef:
        key: secret/qualys
        property: activation_id
    - secretKey: customer-id
      remoteRef:
        key: secret/qualys
        property: customer_id

Token Rotation

Best practices for token management:

  • Regular Rotation - Rotate API tokens every 90 days
  • Least Privilege - Use tokens with minimal required scopes
  • Audit Logging - Monitor token usage through Qualys audit logs
  • Revocation - Immediately revoke compromised tokens
