Configure Environment Variables

Before triggering container scans in GitHub Actions, you must configure the required secrets and environment variables. These credentials are used to authenticate with the Qualys platform and control scan behavior.

Required Secrets

Configure the following secrets in your GitHub repository or organization:

  1. Navigate to your repository or organization Settings
  2. Click Secrets and variables > Actions
  3. Click New repository secret (or New organization secret)
  4. Add the required secrets listed below
Secret Name Required Description
QUALYS_ACCESS_TOKEN Yes Your Qualys API access token with Container Security permissions
GITHUB_TOKEN Auto Automatically provided by GitHub Actions for SARIF upload and issue creation

Generate Qualys Access Token

To generate an access token with Container Security permissions:

  1. Log in to the Qualys platform
  2. Navigate to Administration > User Management
  3. Select your user account or create a service account
  4. Generate an API token with Container Security scope enabled
  5. Copy the token value securely
Important

Store your access token securely. Never commit tokens directly in your workflow files or repository code.

Action Inputs

The following inputs are available for the GitHub Action:

Input Required Default Description
qualys_access_token Yes - Qualys API access token
qualys_pod Yes - Qualys platform region (US1, US2, US3, US4, EU1, EU2, CA1, IN1, AU1, UK1, AE1, KSA1)
image_id Yes - Container image to scan (e.g., nginx:latest, myregistry.azurecr.io/app:v1.0)
platform No linux/amd64 Target platform for multi-arch images (linux/amd64, linux/arm64)
scan_secrets No true Enable secrets detection scanning
use_policy_evaluation No false Use Qualys cloud policies instead of local thresholds
max_critical No 0 Maximum allowed critical vulnerabilities (0 = fail on any)
max_high No 0 Maximum allowed high vulnerabilities
max_medium No -1 Maximum allowed medium vulnerabilities (-1 = unlimited)
max_low No -1 Maximum allowed low vulnerabilities (-1 = unlimited)
create_issues No false Create GitHub Issues for discovered vulnerabilities
issue_labels No security,vulnerability Labels to apply to created issues

Action Outputs

The action provides the following outputs for use in subsequent workflow steps:

Output Description
critical_count Number of critical vulnerabilities found
high_count Number of high vulnerabilities found
medium_count Number of medium vulnerabilities found
low_count Number of low vulnerabilities found
policy_result Policy evaluation result (ALLOW, DENY, AUDIT)
sarif_path Path to generated SARIF report file
json_path Path to generated JSON report file
issues_created Number of GitHub Issues created
