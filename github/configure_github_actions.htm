Configure GitHub Actions

This section explains how to add the Qualys Container Scan action to your GitHub Actions workflow.

Add the Workflow File

  1. In GitHub, navigate to your repository
  2. Click the Actions tab
  3. Click New workflow or set up a workflow yourself
  4. Create a new file at .github/workflows/container-scan.yml
  5. Add the workflow configuration as shown below
  6. Commit the file to your repository

Basic Workflow Example

The following example scans a container image on every push and pull request:

name: Container Security Scan

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Build container image
        run: docker build -t my-app:${{ github.sha }} .

      - name: Scan container image
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: my-app:${{ github.sha }}
          max_critical: 0
          max_high: 5

      - name: Upload SARIF results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: qualys-scan-results.sarif
Note

The workflow must include the actions/checkout step before the scan action to ensure the repository files are available.

Workflow with Policy Evaluation

Use Qualys cloud policies for centralized policy management:

name: Container Security Scan with Policy

on:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Build container image
        run: docker build -t my-app:${{ github.sha }} .

      - name: Scan container image
        id: scan
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: my-app:${{ github.sha }}
          use_policy_evaluation: true
          scan_secrets: true

      - name: Check policy result
        run: |
          echo "Policy Result: ${{ steps.scan.outputs.policy_result }}"
          echo "Critical: ${{ steps.scan.outputs.critical_count }}"
          echo "High: ${{ steps.scan.outputs.high_count }}"

Workflow with Issue Creation

Automatically create GitHub Issues for discovered vulnerabilities:

name: Container Scan with Issue Tracking

on:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
      issues: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Scan container image
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: nginx:latest
          create_issues: true
          issue_labels: security,vulnerability,container

      - name: Upload SARIF results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: qualys-scan-results.sarif
Important

When using create_issues: true, ensure your workflow has the issues: write permission.

Scanning Private Registry Images

To scan images from private container registries, authenticate before running the scan:

name: Scan Private Registry Image

on:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Login to Azure Container Registry
        uses: azure/docker-login@v1
        with:
          login-server: myregistry.azurecr.io
          username: ${{ secrets.ACR_USERNAME }}
          password: ${{ secrets.ACR_PASSWORD }}

      - name: Scan container image
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: myregistry.azurecr.io/my-app:latest

Multi-Architecture Scanning

Scan specific platform variants of multi-architecture images:

- name: Scan ARM64 image
  uses: qualys/container-scan-action@v1
  with:
    qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
    qualys_pod: US1
    image_id: my-app:latest
    platform: linux/arm64
