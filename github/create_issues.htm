Create GitHub Issues

The Qualys Container Scan action can automatically create GitHub Issues for discovered vulnerabilities. This integrates security findings into your existing issue tracking workflow, making it easier to assign, track, and remediate vulnerabilities.

Enable Issue Creation

Set create_issues: true in your workflow configuration:

name: Container Scan with Issue Creation

on:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
      issues: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Scan container image
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: my-app:latest
          create_issues: true
          issue_labels: security,vulnerability,container
Important

The workflow must have issues: write permission to create issues.

Issue Configuration Options

Input Default Description
create_issues false Enable automatic issue creation
issue_labels security,vulnerability Comma-separated list of labels to apply
issue_severity_threshold high Minimum severity to create issues (critical, high, medium, low)

Issue Content

Each created issue includes:

  • Title - CVE ID and affected package name
  • Severity Label - Automatically applied based on CVSS score
  • Description - Vulnerability details and impact
  • Affected Package - Package name and vulnerable version
  • Fixed Version - Recommended upgrade version (if available)
  • Container Image - Image name and tag that was scanned
  • References - Links to CVE databases and advisories

Example Issue

A typical generated issue looks like:

Title: [CRITICAL] CVE-2023-12345 in openssl 1.1.1k

Labels: security, vulnerability, container, critical

Body:
## Vulnerability Details

**CVE ID:** CVE-2023-12345
**Severity:** Critical (CVSS 9.8)
**Package:** openssl
**Installed Version:** 1.1.1k
**Fixed Version:** 1.1.1l

## Description

A buffer overflow vulnerability exists in OpenSSL that allows
remote attackers to execute arbitrary code...

## Affected Image

- **Image:** my-app:latest
- **Digest:** sha256:abc123...
- **Scanned:** 2024-01-15T10:30:00Z

## Remediation

Update the openssl package to version 1.1.1l or later.

## References

- https://nvd.nist.gov/vuln/detail/CVE-2023-12345
- https://www.openssl.org/news/secadv/...

Duplicate Prevention

The action checks for existing open issues with the same CVE ID before creating new ones. This prevents duplicate issues when:

  • The same vulnerability is detected in multiple scans
  • Multiple images share the same vulnerable package
  • Scheduled scans run repeatedly

Severity-Based Issue Creation

Create issues only for high-severity vulnerabilities:

- name: Scan container image
  uses: qualys/container-scan-action@v1
  with:
    qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
    qualys_pod: US1
    image_id: my-app:latest
    create_issues: true
    issue_severity_threshold: critical

Custom Labels

Apply custom labels to organize issues:

- name: Scan container image
  uses: qualys/container-scan-action@v1
  with:
    qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
    qualys_pod: US1
    image_id: my-app:latest
    create_issues: true
    issue_labels: security,container,team-platform,priority-high
Tip

Create labels in your repository before running the workflow. The action will use existing labels but cannot create new ones.

Output: Issues Created Count

Access the number of issues created in subsequent steps:

- name: Scan container image
  id: scan
  uses: qualys/container-scan-action@v1
  with:
    qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
    qualys_pod: US1
    image_id: my-app:latest
    create_issues: true

- name: Report issues created
  run: echo "Created ${{ steps.scan.outputs.issues_created }} issues"
