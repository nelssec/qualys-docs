Trigger Scan

Container security scans can be triggered automatically through various GitHub Actions events. This section explains the different trigger options and how to configure them.

Push and Pull Request Triggers

The most common triggers scan containers on code changes:

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

With this configuration:

  • Scans run on every push to main or develop branches
  • Scans run on pull requests targeting the main branch
  • Pull request scans help identify vulnerabilities before merging

Scheduled Scans

Use cron notation to schedule scans at regular intervals:

on:
  schedule:
    # Run daily at 2:00 AM UTC
    - cron: '0 2 * * *'

    # Run weekly on Monday at 9:00 AM UTC
    - cron: '0 9 * * 1'

Scheduled scans are useful for:

  • Detecting newly disclosed vulnerabilities in existing images
  • Regular security compliance checks
  • Monitoring production container images

Manual Triggers

Enable manual workflow execution with input parameters:

on:
  workflow_dispatch:
    inputs:
      image:
        description: 'Container image to scan'
        required: true
        default: 'nginx:latest'
      pod:
        description: 'Qualys POD region'
        required: true
        default: 'US1'
        type: choice
        options:
          - US1
          - US2
          - EU1
          - CA1

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: Scan container image
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: ${{ inputs.pod }}
          image_id: ${{ inputs.image }}

Path-Based Triggers

Only trigger scans when Dockerfile or container-related files change:

on:
  push:
    branches: [main]
    paths:
      - 'Dockerfile'
      - 'docker-compose.yml'
      - '.dockerignore'
      - 'src/**'

Tag-Based Triggers

Scan container images when release tags are created:

on:
  push:
    tags:
      - 'v*'

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Extract tag name
        id: tag
        run: echo "version=${GITHUB_REF#refs/tags/}" >> $GITHUB_OUTPUT

      - name: Build and scan release image
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: my-app:${{ steps.tag.outputs.version }}

Conditional Scanning

Use conditional logic to control when scans run:

jobs:
  scan:
    runs-on: ubuntu-latest
    # Only scan on main branch or when PR is labeled 'security'
    if: github.ref == 'refs/heads/main' || contains(github.event.pull_request.labels.*.name, 'security')
    steps:
      - name: Scan container image
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: my-app:latest

Matrix Scanning

Scan multiple images in parallel using a matrix strategy:

jobs:
  scan:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        image:
          - nginx:latest
          - redis:7
          - postgres:15
    steps:
      - name: Scan ${{ matrix.image }}
        uses: qualys/container-scan-action@v1
        with:
          qualys_access_token: ${{ secrets.QUALYS_ACCESS_TOKEN }}
          qualys_pod: US1
          image_id: ${{ matrix.image }}
